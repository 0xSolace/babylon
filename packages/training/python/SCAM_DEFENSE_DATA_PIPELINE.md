# Scam Defense Data Pipeline

This pipeline keeps one canonical scam-defense corpus and reprocesses it into the
provider and framework formats needed by Babylon, OpenAI, Anthropic, Hermes,
ElizaOS, and OpenClaw.

## Canonical Row Contract

Every training row should carry:

- `record_id`
- `group_id`
- `scenario_id`
- `category`
- `prompt`
- `system_prompt`
- `user_prompt`
- `response`
- `chosen_action`
- `response_format`
- `available_actions`
- `source_kind`
- `source_dataset`
- `source_family`

`available_actions` must include the chosen action plus an expanded catalog of
benign and irrelevant distractor actions. This keeps the model from learning that
the only possible outputs are the narrow benchmark actions.

## Canonical Flow

1. Babylon / ScamBench catalog stages are exported by `scripts/export_scam_defense_trajectories.py`.
2. External reviewed corpora are materialized by `scripts/materialize_external_scam_data.py`.
3. Synthetic conversations are generated by `scripts/generate_synthetic_conversations.py`.
4. The export step mixes catalog, external, and synthetic rows into:
   - trajectory JSONL for training
   - canonical `corpus/training_examples.jsonl`
   - reprocessed `corpus/formats/*.jsonl`
5. Provider/framework-specific bundles are regenerated from the canonical corpus by `scripts/reprocess_scam_defense_corpus.py`.
6. Babylon agentic trajectory exports can be normalized into the same corpus contract with `scripts/export_babylon_scam_corpus.py`.
7. Optional Groq judge bundles can be attached after the fact with `scripts/build_groq_judge_bundles.py`.
8. The current canonical corpus, generated scripts, and reasoning packs can be assembled into one local HF-ready Parquet dataset repo with `scripts/assemble_scam_defense_hf_dataset.py`.
9. The assembled HF-ready dataset repo can be checked for schema, split leakage, and local loadability with `scripts/validate_scam_defense_hf_dataset.py`.

## Output Formats

The canonical corpus can be reprocessed into:

- `canonical.jsonl`
- `openai-chat.jsonl`
- `anthropic-messages.jsonl`
- `generic-chat.jsonl`
- `hermes-bridge.jsonl`
- `eliza-room.jsonl`
- `openclaw-session.jsonl`

Each bundle preserves:

- source metadata
- chosen action
- expanded action catalog
- user/system prompts
- assistant response

## Commands

Export a mixed corpus:

```bash
python scripts/export_scam_defense_trajectories.py \
  --output-dir training-data/scam-defense-export/latest \
  --include-external-materialized \
  --include-synthetic-training \
  --include-format-recovery
```

Reprocess an existing canonical corpus:

```bash
python scripts/reprocess_scam_defense_corpus.py \
  --input training-data/scam-defense-export/latest/corpus \
  --output-dir training-data/scam-defense-export/latest/reprocessed
```

Normalize Babylon trajectory exports into the same corpus contract:

```bash
python scripts/export_babylon_scam_corpus.py \
  --source-dir training-data-output/trajectories \
  --output-dir training-data/scam-defense-export/babylon-agentic
```

Attach Groq judge bundles to a canonical corpus:

```bash
python scripts/build_groq_judge_bundles.py \
  --input training-data/scam-defense-export/latest/corpus \
  --input-type training-rows \
  --output-dir training-data/scam-defense-export/latest/judge \
  --model <groq-judge-model> \
  --mode relative
```

Build a diversified ChatML corpus while preserving the canonical action contract:

```bash
python scripts/build_diversified_training_data.py \
  --synthetic-dir trained_models/scam-defense-.../training_data \
  --external-dir training-data/merged-threat-materialized/<run> \
  --output-dir trained_models/scam-defense-.../training_data
```

Assemble one local HF-ready Parquet dataset repo from the canonical corpus plus synthesized scripts:

```bash
python scripts/assemble_scam_defense_hf_dataset.py \
  --output-dir training-data/hf-ready-scam-defense/latest
```

The assembly script also updates `training-data/hf-ready-scam-defense/latest` as a symlink to the newest timestamped dataset directory, so downstream checks can use one stable local path.

Validate the local HF-ready dataset repo before upload:

```bash
python scripts/validate_scam_defense_hf_dataset.py \
  --dataset-dir training-data/hf-ready-scam-defense/latest \
  --output training-data/hf-ready-scam-defense/latest/metadata/validation-report.json
```
